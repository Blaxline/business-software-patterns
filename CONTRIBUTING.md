# Contributing

This repository is developed from recurring patterns found in real business software.

## What belongs here

A contribution should describe a recurring operational problem and provide enough detail to help someone design, implement or operate a reliable solution.

Patterns should be:

- generally applicable;
- implementation-aware;
- explicit about tradeoffs;
- grounded in operational reality;
- independent of unnecessary framework choices.

A pattern should not be added simply because an architecture technique exists. It should solve a recurring business-software problem.

## Safety and confidentiality

Do not include client names, proprietary process details, credentials, personal data or code copied from private systems. Use synthetic examples and generalized language.

## Quality bar

Explain when a simpler approach is better. Include failure modes, operational ownership and the evidence needed to understand the system after launch.
