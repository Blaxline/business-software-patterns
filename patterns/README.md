# Pattern library

This library documents recurring problems in business software. Each pattern starts with the operation: the people, rules, decisions, exceptions, evidence and systems involved.

Patterns are intentionally implementation-aware without being tied to a framework, vendor or workflow engine.

## Pattern standard

Every substantial pattern should cover:

1. The operational problem.
2. When to use it and when not to.
3. The business model and important invariants.
4. Implementation considerations.
5. Failure modes and operational consequences.
6. A generalized example.
